## Executive summary

**Bottom line: NOT MVP-ready and NOT enterprise-ready today.** An autonomous 13-agent Fable review found **128 distinct issues** (9 P0, 38 P1, 53 P2, 28 P3) across correctness, security, completeness, dead code, architecture, and operations.

The dominant theme is **"built in code, but not wired into the running/deployed system."** The event/crisis pipeline is off by default in the shipped compose; PHI encryption and the tamper-evident audit chain are armed in *zero* services; the LangGraph Postgres checkpointer and the durable DLQ default to in-memory; RS256 is implemented but unprovisioned in every deployment config. And a **confirmed hard blocker**: every Docker image fails to build because all 10 Dockerfiles `COPY`/install a `requirements-runtime.txt` that **does not exist in the repo** — which means nothing has ever actually built or run end-to-end on real infrastructure.

The 9 P0s collapse to ~5-6 root problems (the broken Docker build surfaces ~3 times as missing/drift/bug/ops-gap): (1) **Docker images cannot build**, (2) the **crisis/event plane is off / not drained** in the deployed stack, (3) **PHI encryption + audit logging are dead guards** wired nowhere (a HIPAA blocker), (4) the **memory write path is orphaned** (nothing stores conversation content), (5) **conversation state is not durable** (InMemorySaver only). Most P0s are build- and deployment-wiring gaps rather than broken business logic — good news, because they are fixable, but they confirm the system has not been exercised against real Postgres/Redis/Kafka/Weaviate yet.
