## CRITICAL — Verified Open (3)

### C-01 remaining | Multi-worker JWT revocation broken
- **Location**: [src/solace_security/middleware.py:132](src/solace_security/middleware.py#L132)
- **Current state**: `_get_jwt_manager()` hardcodes `InMemoryTokenBlacklist()`
- **Why it matters**: In multi-worker deployments (uvicorn --workers N), token revocation in one worker does not propagate to others. Violates HIPAA audit requirements for session revocation.
- **Fix**: Replicate the pattern already used in [services/user-service/src/main.py:186-196](services/user-service/src/main.py#L186) — conditional `RedisTokenBlacklist` when Redis client is available, fall back to `InMemoryTokenBlacklist` only when `ENVIRONMENT=testing`.
- **Sprint**: 1 Day 1
- **TDD**: Write test asserting `_get_jwt_manager()` returns RedisTokenBlacklist when Redis URL set.

### NEW-03 | DiagnosisSession.messages not encrypted at rest
- **Location**: [src/solace_infrastructure/database/entities/diagnosis_entities.py:76](src/solace_infrastructure/database/entities/diagnosis_entities.py#L76)
- **Current state**: `__phi_fields__: ClassVar[list[str]] = ["summary"]` — `messages` column (JSONB conversation history) not in list
- **Additional blocker**: [src/solace_infrastructure/database/base_models.py:429](src/solace_infrastructure/database/base_models.py#L429) — `encrypt_phi_fields` only handles `isinstance(value, str)` types. Simply adding `messages` to the list won't encrypt it because JSONB is a list/dict type.
- **Why it matters**: Conversation history is PHI per HIPAA. Currently stored as plaintext JSONB.
- **Fix (2 parts)**:
  1. Enhance `encrypt_phi_fields` / `decrypt_phi_fields` in `base_models.py` to serialize list/dict via `json.dumps` before encrypting and `json.loads` after decrypting
  2. Add `"messages"` to `DiagnosisSession.__phi_fields__`
- **Sprint**: 1 Day 2
- **TDD**: Round-trip test storing a known-content list in `messages`, reading back, verifying plaintext matches + raw DB cell is ciphertext.

### NEW-04 | Hypothesis evidence not encrypted at rest
- **Location**: [src/solace_infrastructure/database/entities/diagnosis_entities.py:208](src/solace_infrastructure/database/entities/diagnosis_entities.py#L208)
- **Current state**: `class Hypothesis(ClinicalBase)` declares no `__phi_fields__`. Inherits default `[]`.
- **Fields to protect**: `supporting_evidence`, `contra_evidence`, `challenge_results`, `criteria_met`, `criteria_missing`, `hitop_dimensions` — all JSONB, all clinical content

- **Sprint**: 1 Day 2

## P0 — Critical (crisis safety + data integrity)

### REV-01 | Kafka event plane is filled but never drained — no domain event reaches the bus
- **Location**: [src/solace_events/publisher.py:301,333-374](src/solace_events/publisher.py#L301) (`OutboxPoller`/`flush_outbox` — zero callers in `services/`); per-service wiring: safety builds `SafetyService` with no publisher ([services/safety_service/src/main.py:119-123](services/safety_service/src/main.py#L119)); therapy `initialize_event_bridge` raises a swallowed `TypeError` at startup ([services/therapy_service/src/main.py:188,196-197](services/therapy_service/src/main.py#L188)); diagnosis dispatcher never injected ([services/diagnosis_service/src/main.py:128](services/diagnosis_service/src/main.py#L128)).
- **Why it matters**: `use_outbox=True` everywhere but nothing polls the outbox, so `safety.crisis.detected` and the whole audit/analytics event trail never publish. Broad `try/except` in each lifespan defeats the fail-loud production guards.
- **Fix**: Start an `OutboxPoller` (or call `flush_outbox`) in each service lifespan; inject publishers/dispatchers where missing; narrow the lifespan `except` so wiring failures fail loud in production.

### REV-02 | Crisis scoring can classify an explicit suicidal statement as ELEVATED (no auto-escalation)
- **Location**: [services/safety_service/src/domain/crisis_detector.py:721-740](services/safety_service/src/domain/crisis_detector.py#L721) (fusion divides by the full weight sum even when sentiment/pattern/history are absent → a lone 0.95 keyword yields ~0.62-0.67, below HIGH 0.7 / CRITICAL 0.9); LLM averaging at `:783` can lower it further; no max-severity override.
- **Compounders**: protective-factor adjustment mutates `risk_score` after `crisis_level` is derived ([service.py:171-179](services/safety_service/src/domain/service.py#L171)); sentiment neutral-floor bias ([sentiment_analyzer.py:525-539](services/safety_service/src/ml/sentiment_analyzer.py#L525)); negation check only inspects the first keyword occurrence (`:274-288`); risk history is per-process.
- **Fix**: Add a max-severity override so any CRITICAL-tier keyword floors the level at HIGH; normalize fusion by active-signal weight, not total weight; derive `crisis_level` after protective-factor adjustment.

### REV-03 | Crisis HTTP notification path broken end-to-end by route shadowing
- **Location**: [services/user-service/src/api.py:811](services/user-service/src/api.py#L811) — `GET /users/{user_id}` is registered before `/users/on-call-clinicians` (`:940`), so the literal path is captured by the path-param route → 422 on every clinician lookup from safety ([clinician_registry.py:146](services/safety_service/src/infrastructure/clinician_registry.py#L146)) and notification ([consumers.py:482](services/notification-service/src/consumers.py#L482)).
- **Why it matters**: With REV-01 killing the Kafka path, **no crisis alert reaches a clinician by either path** except the hardcoded fallback email.
- **Fix**: Register the static `/users/on-call-clinicians` route before the `/users/{user_id}` path-param route.

### REV-04 | Diagnosis persistence silently writes nothing; RLS lockout latent; migrations never run
- **Location**: `save_record` omits NOT-NULL `encryption_key_id` → every insert fails, swallowed as a warning ([postgres_repository.py:206](services/diagnosis_service/src/infrastructure/postgres_repository.py#L206), [service.py:453-454](services/diagnosis_service/src/domain/service.py#L453)); `save_session` writes columns absent from migration 001 (`:85-88`). Migration 002 FORCEs RLS keyed on `app.current_user_id`, but no service sets that GUC ([002_enable_rls_clinical_tables.py:55-77](migrations/versions/002_enable_rls_clinical_tables.py#L55)) — once applied, clinical reads return zero rows and inserts fail WITH CHECK. No deployment path runs Alembic ([alembic.ini:32](alembic.ini#L32) wrong DSN; compose/CI never migrate).
- **Cross-ref**: extends H-56 (RLS) and the H-04 persistence line.
- **Fix**: Populate `encryption_key_id` on save; reconcile `save_session` columns with the migration; set the `app.current_user_id` GUC per request/session before RLS is enabled; wire an Alembic `upgrade head` step into deploy/compose and fix the DSN.

### REV-05 | Escalation is in-memory by default and writes a stale row once; notify timeout blocks `/check`
- **Location**: in-memory repo is the runtime default ([services/safety_service/src/main.py:115-118](services/safety_service/src/main.py#L115)); escalation row saved once pre-workflow and never updated ([escalation.py:735,817-832](services/safety_service/src/domain/escalation.py#L735)); `notification_timeout_seconds=300` per attempt × 4 retries blocks the `/check` request for minutes ([escalation.py:140,213-252](services/safety_service/src/domain/escalation.py#L140)).
