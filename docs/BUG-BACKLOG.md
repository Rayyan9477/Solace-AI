## P0 — Critical (crisis safety + data integrity)

### REV-01 | Kafka event plane is filled but never drained — no domain event reaches the bus
- **Location**: [src/solace_events/publisher.py:301,333-374](src/solace_events/publisher.py#L301) (`OutboxPoller`/`flush_outbox` — zero callers in `services/`); per-service wiring: safety builds `SafetyService` with no publisher ([services/safety_service/src/main.py:119-123](services/safety_service/src/main.py#L119)); therapy `initialize_event_bridge` raises a swallowed `TypeError` at startup ([services/therapy_service/src/main.py:188,196-197](services/therapy_service/src/main.py#L188)); diagnosis dispatcher never injected ([services/diagnosis_service/src/main.py:128](services/diagnosis_service/src/main.py#L128)).
- **Why it matters**: `use_outbox=True` everywhere but nothing polls the outbox, so `safety.crisis.detected` and the whole audit/analytics event trail never publish. Broad `try/except` in each lifespan defeats the fail-loud production guards.
- **Fix**: Start an `OutboxPoller` (or call `flush_outbox`) in each service lifespan; inject publishers/dispatchers where missing; narrow the lifespan `except` so wiring failures fail loud in production.

### REV-02 | Crisis scoring can classify an explicit suicidal statement as ELEVATED (no auto-escalation)
- **Location**: [services/safety_service/src/domain/crisis_detector.py:721-740](services/safety_service/src/domain/crisis_detector.py#L721) (fusion divides by the full weight sum even when sentiment/pattern/history are absent → a lone 0.95 keyword yields ~0.62-0.67, below HIGH 0.7 / CRITICAL 0.9); LLM averaging at `:783` can lower it further; no max-severity override.
- **Compounders**: protective-factor adjustment mutates `risk_score` after `crisis_level` is derived ([service.py:171-179](services/safety_service/src/domain/service.py#L171)); sentiment neutral-floor bias ([sentiment_analyzer.py:525-539](services/safety_service/src/ml/sentiment_analyzer.py#L525)); negation check only inspects the first keyword occurrence (`:274-288`); risk history is per-process.
- **Fix**: Add a max-severity override so any CRITICAL-tier keyword floors the level at HIGH; normalize fusion by active-signal weight, not total weight; derive `crisis_level` after protective-factor adjustment.

### REV-03 | Crisis HTTP notification path broken end-to-end by route shadowing
- **Location**: [services/user-service/src/api.py:811](services/user-service/src/api.py#L811) — `GET /users/{user_id}` is registered before `/users/on-call-clinicians` (`:940`), so the literal path is captured by the path-param route → 422 on every clinician lookup from safety ([clinician_registry.py:146](services/safety_service/src/infrastructure/clinician_registry.py#L146)) and notification ([consumers.py:482](services/notification-service/src/consumers.py#L482)).
- **Why it matters**: With REV-01 killing the Kafka path, **no crisis alert reaches a clinician by either path** except the hardcoded fallback email.
- **Fix**: Register the static `/users/on-call-clinicians` route before the `/users/{user_id}` path-param route.

### REV-04 | Diagnosis persistence silently writes nothing; RLS lockout latent; migrations never run
- **Location**: `save_record` omits NOT-NULL `encryption_key_id` → every insert fails, swallowed as a warning ([postgres_repository.py:206](services/diagnosis_service/src/infrastructure/postgres_repository.py#L206), [service.py:453-454](services/diagnosis_service/src/domain/service.py#L453)); `save_session` writes columns absent from migration 001 (`:85-88`). ### REV-32 | Split environment source silently disables SSL + audit HMAC + encryption-key ban in "production"  *(P1 — surfaced by the A.6 security review, 2026-07-24)*
- **Location**: three shared security controls read the **bare** `ENVIRONMENT` — `PostgresSettings.get_effective_ssl_mode` ([postgres.py:70](src/solace_infrastructure/postgres.py#L70)), `AuditSettings.validate_hmac_key_for_environment` ([audit.py:80](src/solace_security/audit.py#L80)), and the dev-key ban in `EncryptionSettings` ([encryption.py:71](src/solace_security/encryption.py#L71)). But services decide "am I production" from a **prefixed** var, e.g. `THERAPY_ENVIRONMENT` (`env_prefix="THERAPY_"`, [config.py:168,186](services/therapy_service/src/config.py#L168)), which is what gates the fail-loud PHI-encryption block ([main.py:100-103](services/therapy_service/src/main.py#L100)).
- **Why it matters (HIPAA)**: set `THERAPY_ENVIRONMENT=production` but forget the bare `ENVIRONMENT` and, with no error: (a) `get_effective_ssl_mode` sees `development` → `prefer` is not upgraded → `get_ssl_context()=None` → asyncpg connects **unencrypted** (PHI in transit in the clear — undoes H-39); (b) a missing `AUDIT_HMAC_KEY` no longer raises → audit chain degrades to plain, forgeable SHA-256; (c) `EncryptionSettings.for_development()` insecure keys become usable. One missing/misnamed var silently defeats three PHI controls at once.
- **Fix**: derive the environment from a single canonical source that every module and service reads; at minimum add a startup assertion (fail-fast in prod) that bare `ENVIRONMENT` matches the service's resolved `environment`. This is the security-critical facet of the "inconsistent env gates" runner-up.
- **Status**: 🔴 **OPEN.** Documented deployment invariant added to H-39 status + KNOWN-LIMITATIONS §3. Code unification scheduled with the env-gate standardization in **D.1**; the deploy-time verification (that a prod stack actually sets `ENVIRONMENT=production`) lands at **B.3** when the staging stack is stood up. Until then, **production/staging deployments MUST set the bare `ENVIRONMENT` var** for the A.6/H-39 controls to activate.
