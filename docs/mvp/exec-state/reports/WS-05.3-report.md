## Design notes
- Hop names are compared by exact string match. Only a top-level `HopFailure` in `call.excinfo` counts as failing at a hop. A cause chain or an ExceptionGroup is judged "<no hop>" and fails, which is the strict direction.
- `hop()` lets pytest control flow through unchanged: skip, xfail, exit, and BaseException signals such as KeyboardInterrupt or CancelledError. `pytest.fail` and any `Exception` become a `HopFailure`.
- For a listed, active test, the raw outcome is taken from `call.excinfo`, not from `report.outcome`. The manifest therefore overrides `pytest.mark.xfail`, so a marker cannot hide a wrong-hop failure (tested). A test that imperatively calls `pytest.xfail()` or uses `xfail(run=False)` counts as failing with no hop.
- On a FAIL verdict the original traceback is kept. The verdict is added as a "solace expected-failure manifest" section, and the crash line now starts with it, so it shows first in the short summary and the junit message. An XPASS failure uses a plain-string longrepr, as pytest's own XPASS(strict) does.
- The stale check runs before `-k`, `-m` and `--deselect` narrow the item list, because its modifyitems hook is tryfirst. Files narrowed by a `file::name` argument are exempt (tested), and the check is skipped under `--lf`. A stale entry sets exit code 1 at session finish and is printed in the terminal summary on stdout. An otherwise green run then exits 1 (tested).
- Due entries are listed in the terminal summary as "due manifest entry: ...". The word "xfailed" never appears in plugin output.
- The extra session hooks (collectreport, sessionfinish, terminal_summary) live on a reporter object that pytest_configure registers. That way the conftest imports exactly the three hooks the brief names.

## Additions beyond the brief (all fail loud)
- Duplicate YAML keys are rejected.
- Unknown keys at any level are rejected.
- `test_id` must contain `::`, use forward slashes, and name a test in the manifest's own directory relative to the rootdir.
- Two entries with the same test_id and overlapping profiles are an error, and so is a node id that matches two entries with overlapping profiles.
- `profiles` defaults to both dev and strict.
- `SOLACE_BARRIER_WAVE` that is empty or not a non-negative integer is a UsageError (exit 4, tested). A misconfigured barrier therefore cannot silently keep due entries applied.
- `SOLACE_E2E_PROFILE` outside {dev, strict} is a UsageError.
- `SOLACE_MANIFEST_IGNORE` is in effect for any non-empty value.
- The brief's stale test was pseudo-code; it is now complete. I added tests for: a stale entry alone giving exit 1, node-id selection not reported stale, setup-phase hops, the xfail-marker override, profile filtering, fnmatch patterns, invalid barrier values, schema errors naming the file and key, and hop control flow.
- In the test helper: the subprocess env also drops `SOLACE_E2E_PROFILE` for hermeticity, and `_run`'s semicolon line is split for ruff E702. Brief values are otherwise verbatim.

## Concerns
1. Skips are passed through unchanged. A listed, active test that is skipped (for example by `require_docker`) shows as skipped, not failed. The manifest never turns anything into a pass, but barrier and E2E runs must keep `SOLACE_REQUIRE_REALINFRA=1` (WS-05.2/05.4) so that missing infrastructure fails instead of skipping. Making skips fail would turn every docker-less `pytest tests` run red.
2. `ManifestError` is an alias of `pytest.UsageError`, not a subclass, because pytest marks UsageError `@final` (mypy flagged it).
3. tests/conftest.py now imports `solace_testing`, which adds about 0.6s of pydantic and structlog import and needs `src` on PYTHONPATH. Every test under tests/ already needs that. A bad `SOLACE_E2E_PROFILE` or `SOLACE_BARRIER_WAVE` value now aborts any run under tests/ with exit 4. That is intended, but CI templates must not set them to empty strings.
4. Manifests are honoured only under tests/: the makereport hook is scoped to that conftest. A manifest placed under services/ is ignored unless the run passes `-p solace_testing.e2e_manifest`. Subdirectories do not inherit a parent manifest; each directory owns its own.
5. To write an fnmatch pattern for a parametrized id, `[` must be escaped as `[[]`. An exact node id always matches literally. A pattern that matches nothing is caught as a stale entry.
6. WS-05.5 creates tests/system/expected_failures.yaml and other tasks create later manifests. They must follow the strict schema: `version` is required and unknown keys are rejected. test_mvp_039_repo_manifests_are_valid enforces this.

## Fixes
1. **Due entries and xfail.**
   - Due items are now stashed (`_DUE_KEY`). The judge takes the outcome from `call.excinfo` and drops `wasxfail`.
   - A failure gives "due manifest entry <id> (target wave N) must pass at barrier wave M". A pass is restored to "passed", but only when pytest's xfail had changed it: wasxfail was set, or the report carries a strict-XPASS longrepr. A pass that something else failed stays failed.
   - A static `pytest.mark.xfail` on any item in a directory with a manifest (closest marker, so class and module marks count) raises ManifestError: "use expected_failures.yaml, not pytest.mark.xfail, in a directory that has a manifest: <ids>". This applies in every mode, including IGNORE.
   - A run-time marker (`request.node.add_marker`) or an imperative `pytest.xfail()` on an unlisted item in such a directory is undone the same way, including under IGNORE.
   - Reconciling the request: a due entry with a *static* marker now stops at collection (exit 4). So the requested "due entry carrying an xfail marker gives 1 failed, exit 1" test uses a marker added at run time. That is the path a collection-time ban cannot see, and the judge must catch it. The static marker has its own test (exit 4 plus the message). The edge test's marker case was also moved to a run-time marker.
2. **Skips at a barrier.**
   - When SOLACE_BARRIER_WAVE is set, a skip of a listed item for the current profile, active or due, becomes failed: "manifest-listed test skipped during barrier wave N; listed tests must run". This covers marker skips, skipif, fixture skips and imperative skips.
   - pytest_collectreport now records skipped module nodeids. Entries whose file_part matches a skipped module fail the session (exit 1) and are listed in the summary as "manifest-listed module skipped during barrier wave N: ...". This covers importorskip and allow_module_level skips.
   - Outside barrier runs, behaviour is unchanged (tested: 2 skipped, exit 0).
3. **Literal brackets.** A shared `_glob_match` uses `fnmatch.fnmatchcase(name, pattern.replace("[", "[[]"))` after an exact-match check. It is used for item matching, the stale check and the skipped-module check. Only `*` and `?` are wildcards. The docstring's escaping note is replaced. This removes concern 5 above.
4. **Wave bound.** `MAX_WAVE = 5`. `_wave` rejects values above it for both target_wave and remove_by_wave, with the existing file-and-key message ("must be an integer from 0 to 5"). Schema tests cover both keys.
