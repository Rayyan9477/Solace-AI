## Deviations from the brief
1. Form (a) instead of the brief's `start_service_runtime`/stop-after-yield (phaseB-common wins); consumer stop via `register_shutdown`.
2. Event bridge start: strict propagates; non-strict logs `notification_event_bridge_unavailable` (error_type only) and registers a
   critical `event_bridge` readiness check `(False, "unavailable")`. The brief's unguarded call breaks dev/test boot without a broker
   (old code had a try/except). Same pattern as safety-service.
3. Strictness = service env OR bare `ENVIRONMENT` (CLAUDE.md platform rule), not `is_strict_environment(settings.service.env)` alone.
4. Strict also refuses `KAFKA_USE_MOCK=true` (a mock consumer reads no broker; sibling of safety WS121-CRI-1).
5. `initialize_safety_consumer` best-effort stops a partially started consumer before re-raising (MVP-287 hygiene).
6. Graceful stop closer is named `safety_consumer_stop` (the runtime's task-cancel closer already uses `safety_consumer`).
