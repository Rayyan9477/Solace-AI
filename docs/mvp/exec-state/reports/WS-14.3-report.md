## Deviations and concerns

1. "token" composition: `FERNET_*`, `TokenService` and `EncryptionService` stay in `main.build_user_service_state`.
   - Why: the joint FERNET key guard covers both the email-verification token key and the field-encryption key. Splitting it would change the guard and its error text.
   - Order of startup failures: tlds, then the Redis strict check, then JWT/password, then the Fernet check. This is the same as before, except that the session, auth and OAuth construction now run before the Fernet check rather than after. None of them raise on configuration.
2. `app.state.service` is now set before the composition finishes, because `start_identity` fills it. A later start-up error still aborts the lifespan, so nothing is served from a half-built state.
3. `_is_strict` moved to `identity_wiring`, and `main` imports it. This keeps one copy of the strictness predicate.
4. `stop_identity` is a logging no-op, because the identity stores own no connections.
5. Log events from the moved code now carry the logger names `src.api_auth` and `src.identity_wiring`. The event names are unchanged.
6. Carried note from WS-14.2 fix1, not changed (this task is verbatim only): `POST /auth/revoke-token` with a well-formed `Bearer <garbage>` header still returns 503.
