## Concerns
1. **Strict still requires `WEAVIATE_API_KEY`** (memory-service reads it, and the opt-in weaviate container uses it). Compose interpolates the whole file, including the profile-disabled weaviate service, so the key stays `:?` even when the vector profile is off. That is harmless, but an operator running without Weaviate must still supply a key. Making it optional would be a registry and IF-02 decision (D-04).
2. **`WEAVIATE_ENABLED=true` without `--profile vector`** leaves memory-service pointing at a weaviate host that does not exist. The service degrades and does not wait for it. The `.env.example` note says the profile is needed; nothing enforces that the two are set together.
3. **Kafka budget.** The 1g strict limit holds the broker's 512m heap, its non-heap memory and a 96m probe JVM every 30 s. On real infra the broker stayed healthy and was not OOM-killed during the test window. A soak run under load (WS-05) is the real proof of capacity.
4. **The kafka-ui pin (`v0.7.2`)** is a tag, not a digest. Digest pinning of the remaining images is WS-03.17.
