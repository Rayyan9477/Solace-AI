# WS-17.2 report: memory PostgresRepository on the shared ConnectionPoolManager pool

**Status:** DONE_WITH_CONCERNS
**Checkpoint:** `WS-17.2:head` tree `4fe39f5482932e34cfed8d6572967ebbe6489c45`

## Change
- `services/memory_service/src/infrastructure/postgres_repo.py`
  - Deleted `PostgresSettings`, along with `create_async_engine`, `async_sessionmaker`, `NullPool`, `AsyncSession`, the engine and session-factory fields, and the pydantic imports.
  - `PostgresRepository(*, pool_name="default")`.
  - `session()` yields `_CoreSession` inside `ConnectionPoolManager.transaction(pool_name)`. The pool sets and resets `app.current_user_id`, so the repository no longer runs its own `set_config`.
  - `initialize()` runs `SELECT 1` (`fetchval`) through `ConnectionPoolManager.acquire`.
  - `close()` is a no-op, because the runtime closes the pool.
  - `get_statistics()` reports `pool` instead of `database` and `host`.
  - New private classes:
    - `_CoreSession.execute` compiles with `PGDialect_asyncpg` and `render_postcompile`. For `Insert`, it fills Python-side defaults (scalar and callable) only where the param is `None` and the column was not set explicitly, so an explicit `None` stays NULL. It maps args via `positiontup`. A `Select` uses `conn.fetch`; any other statement uses `conn.execute`, and the rowcount is parsed from the status string.
    - `_CoreResult` provides `fetchone`, `fetchall`, `scalar` and `rowcount`.
    - `_CoreRow` provides `_mapping` and positional access.
  - JSON values go to the pool's `init_connection` json/jsonb codecs as raw Python objects. The SQLAlchemy JSON serializer is not applied, which avoids double encoding. Values only ever travel as bound arguments and are never rendered or logged.
  - The `Table` objects and every method body are unchanged. That includes the `metadata` column and `user_facts`, which are left for WS-17.5, WS-17.6 and WS-17.11.
- `services/memory_service/tests/test_infrastructure.py`: removed `TestPostgresSettings` and the import. `TestPostgresRepository` uses `PostgresRepository()` and asserts `stats["pool"] == "default"`.
- `services/memory_service/tests/conftest.py` (new): `RecordingConnection`, `RecordingPoolManager` and the `recording_cpm` fixture, which monkeypatches `acquire`, `transaction`, `close_pool` and `close_all_pools`.
- `services/memory_service/tests/test_mvp_if03_repo_shared_pool.py` (new): the 3 tests verbatim from the brief.
- `services/memory_service/src/main.py`: no change needed. It already calls `PostgresRepository()` only when `runtime.pg_pool` is set.

## Deviations and concerns
1. **No real-Postgres check.** The brief says real infra: no. The compiled SQL carries typed casts such as `$1::UUID`, `$9::JSON` and `$n::NUMERIC(5, 4)`, plus the float or Decimal binds in the `apply_batch_decay` `case()` expression. These have not been executed against real asyncpg or Postgres. The first real-infra memory run should cover one write, one read and the decay.
2. **No separate RED for the `test_infrastructure.py` edit.** The new `stats["pool"]` assertion would KeyError against the old code, but I did not run it separately before the implementation.
3. **Pre-existing lint.** Ruff reports 2 E712 findings (`is_archived == False`) in unchanged method bodies (lines 295 and 438). I left them because the brief requires the method bodies to stay as they are.
4. **Read path behaviour change.** `get_memory_record` still schedules `_update_access_time` as a background task. That task now borrows a second connection from the shared pool, where before it used the private engine. Behaviour is the same, but it counts against the shared pool size.
5. **Edit method.** I made the edits with a Python string-replace script rather than the Edit tool. The script writes no BOM, so there is no effect on the files.
