## The helpers (crisis-review F6)
- `crisis_episodes(stack, user_id, *, timeout=0.0)`: reads `alert_id::text, status, max_level, sources, page_count`
  of `crisis_alerts` for the user through `Stack.sql`, the user id bound as `:'p1'::uuid` (a non-UUID raises
  ValueError). Order by `opened_at`: `Stack.sql` wraps the query in `json_agg`, which does not promise the CTE's
  order, so the query adds `row_number() OVER (ORDER BY opened_at, alert_id)` and the helper sorts on it, then
  returns only the five columns. Polls every 1 s until at least one row or the timeout (0 = one read). SQL errors
  (e.g. the table missing in W0) are raised at once, not retried.
- `pages_for_episode(stack, address, alert_id)`: `stack.mail.messages(address, "ref <first 8 of alert_id>")`; the id
  is normalised through `UUID` (accepts UUID or any-case text, rejects non-UUIDs).
- `wait_for_episode_page(stack, address, alert_id, timeout)`: the oldest such page; TimeoutError names only the ref
  and the timeout, never an address, subject or mail text.
