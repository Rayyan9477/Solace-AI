# WS-17.2 fix round 1 report (W172-SEC-1)

**Status:** DONE
**Checkpoint:** `WS-17.2:fix1`, tree `5baf90888b7d104f1e12f7566289cadd2fe1ae27`

## Finding
**W172-SEC-1.** When asyncpg cannot encode a bind, its `DataError` message embeds `repr(value)[:40]`. Server-side data errors, such as an invalid text representation, also quote the input. The memory `domain/service.py` callers log with `logger.exception`, so up to 40 characters of user content could reach the logs. The `_CoreSession` docstring also wrongly claimed that values are never logged.

## Fix (`services/memory_service/src/infrastructure/postgres_repo.py`)
- `_CoreSession.execute` now wraps a new `_execute`, which holds the unchanged compile-and-send body. On `asyncpg.exceptions.DataError` it raises a new `DataError` that names only:
  - the argument position (`$n`, parsed from asyncpg's message, or `unknown`);
  - the statement kind (`Insert`, `Update`, `Delete` or `Select`);
  - the original exception type name.
- It raises **outside** the `except` block, so `__cause__` and `__context__` are both `None`. A `raise ... from None` would still leave the original in `__context__`.
- The exception type stays `DataError`, so existing `except DataError` callers are unaffected.
- The docstring is corrected: values never go into the SQL, and a `DataError` is re-raised sanitized with no chained cause or context.
- I checked how the runtime log chain renders exceptions (`runtime/logging.py`). It uses `format_exc_info` and `plain_traceback`, so no frame locals are rendered.

## Test (`services/memory_service/tests/test_mvp_if03_repo_shared_pool.py`)
New test: `test_if03_bind_errors_never_carry_bound_values`.
- A fake connection raises `DataError("invalid input for query argument $4: 'SYNTHETIC-PHI-MARKER-7f3a...' (...)")` from `store_memory_record`.

## Concerns
- **IntegrityError details are not sanitized.** The scope is `DataError` as directed. The `.detail` text of an `IntegrityError` (for example `Key (id)=(...) already exists`) can quote key values. In memory's tables those keys are UUIDs, not content.
