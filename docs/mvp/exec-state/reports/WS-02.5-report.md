### `scripts/db/gen_certs.py`
- **Interface:** `main(argv) -> int` and `python -m scripts.db.gen_certs --out DIR [--san NAME ...] [--ip ADDR ...] [--days N] [--force]`.
- **Exit codes:** 0 written; 1 refused or failed (existing files without `--force`, `--out` is a file, a write error); 2 bad arguments. argparse's SystemExit is turned into the return code. Invalid DNS names, IPs and days are rejected, as is an empty `--out`, which would otherwise mean the current directory.
- **CA (`postgres-ca.crt`):**
  - ECDSA P-256, self-signed, SHA-256.
  - CN `Solace-AI Postgres CA <8 hex>`.
  - BasicConstraints ca=True, pathlen 0, critical.
  - KeyUsage keyCertSign and cRLSign, critical.
  - SubjectKeyIdentifier.
- **Server certificate (`server.crt`):**
  - ECDSA P-256.
  - BasicConstraints ca=False, critical.
  - KeyUsage digitalSignature, critical.
  - ExtendedKeyUsage serverAuth.
  - SubjectAlternativeName, SubjectKeyIdentifier, and an AuthorityKeyIdentifier that matches the CA's SKI.
- **Validity:** `--days` (default 365, at most 3650), with `not_valid_before` back-dated 5 minutes. The CA's validity equals the server certificate's.
- **Key (`server.key`):** PKCS#8 PEM, unencrypted, mode 0600 via `os.open` and `chmod` (on Windows only the read-only bit applies).
- **SANs:** with neither `--san` nor `--ip`, DNS `postgres` and `localhost` plus IP `127.0.0.1`. If either option is given, exactly the names given are used.
- **Writing:**
  - The CA key exists only in memory; nothing else can be signed by this CA.
  - Each file is written to a temporary name in `--out` and then renamed with `os.replace`. No temporary file survives, including on failure.
  - Without `--force`, existing names (`lexists`, so a symlink counts) are never replaced.
- **Output:**
  - stdout is one line, `gen_certs: wrote postgres-ca.crt, server.crt, server.key (the CA's key is not kept)`.
  - Errors go to stderr and name files and the directory only. No PEM is ever printed.

### `scripts/db/pg_tls_entrypoint.sh`
- Plain POSIX sh (the image's busybox ash). Every step is checked explicitly and fails with `solace-pg-entrypoint: error: ...` and exit 1.
- **`SOLACE_PG_TLS`** is `required` or `optional` (the default). Any other value is refused, and the message does not echo it.
- **Argument handling:** a first argument starting with `-` becomes `postgres <args>`, as in the image's own entrypoint. Commands other than `postgres` are exec'd unchanged.
- **Installing the files.** When `$SOLACE_PG_TLS_DIR` (default `/run/secrets`) holds both `server.crt` and `server.key`:
  - Each is copied (`rm -f` then `cp`, under umask 077) to `/var/lib/postgresql/tls`, which is outside PGDATA.
  - Modes are set to dir 0700, crt 0644, key 0600.
  - As root, `chown -R postgres:postgres` gives them to the server user. Running as non-root skips the chown.
  - It appends `-c ssl=on -c ssl_cert_file=... -c ssl_key_file=...`. These come last, so they win over any earlier `-c` of the same name.
- **Required mode:** it also writes `pg_hba.conf` with the brief's three lines plus a comment, mode 0600, and appends `-c hba_file=...`.
- **Fail-closed cases:**
  - Required with neither file: exit 1, naming `server.crt` and `server.key`.
  - Either mode with only one file: exit 1, naming the missing one.
  - Unreadable or non-regular files: exit 1.
  - Optional with neither file: the plain image path.
- **Before exec:** it restores the umask, unsets its variables (none is exported) and runs `exec docker-entrypoint.sh "$@"`.
- **Restart and rotation:** the files are re-installed on every start, so rotation means regenerating the files and restarting the container. A probe confirmed a `docker restart`.

  - `db.internal,%6Cocalhost` dials db.internal and localhost.
- `localhost/x`, `localhost?x=1` and `localhost#x`, which also dial localhost, because the URL parser cuts the host at `/`, `?` and `#`. Decoding alone would not have caught these.
- `127.1` and `2130706433`, which getaddrinfo reads as 127.0.0.1.

**Fix: an allowlist instead of a denylist.**
- In staging and production, each member of the comma list must be one of:
  - a plain DNS name or IPv4 literal (ASCII letters, digits, `_`, `-` and `.`, with at most a trailing dot);
  - a bracketed IPv6 literal.
- A plain remote host still passes; test values include `postgres`, `db.internal`, `solace_postgres`, `10.0.0.5`, `[fd00::5]` and `db1.internal,db2.internal`.
- **Refused:**
  - any `%`;
  - `/`, `?`, `#` or `@`;
  - a `:` outside brackets, which also covers unbracketed IPv6 (asyncpg takes the host up to the first `:`) and `host:port`;
  - spaces, non-ASCII characters and blank members.
- **Still refused, as before:** localhost and `*.localhost`, loopback and unspecified addresses (including IPv4-mapped), and inet_aton spellings (`127.1`, `2130706433`, `0x7f.0.0.1`). Optional hardening: the numeric forms are classified through `socket.inet_aton`.
- The error text names only POSTGRES_HOST. It says the host "is unset, is not a plain host name or address (an IPv6 address goes in brackets), or names this machine ...", and echoes no value.
- After the fix the probe marks every one of those forms as local, while `postgres`, `db.internal` and `[fd00::5]` stay accepted.
