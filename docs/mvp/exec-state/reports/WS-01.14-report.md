## Interfaces produced
- `Finding(rule: str, path: str)`: a frozen dataclass. `str()` gives `"<rule> <path>"`, and `repr()` holds names only.
- `visible_paths(root) -> list[str]`: runs `git -C <root> ls-files --cached --others --exclude-standard -z` (read-only, `check=True`). The result is decoded as UTF-8 with surrogateescape, de-duplicated and sorted.
- `scan(root, paths) -> list[Finding]`: reads each existing regular file as bytes. A listed path that is deleted or not a regular file is skipped. An unreadable file raises `OSError`, so the scan fails closed.
- The five rules work as the brief specifies:
  - The age regex is compiled verbatim from the brief, with the prefix built by concatenation.
  - The planned `deploy/secrets/` set is matched by full regex: `<env>.sops.yaml`, `.sops.yaml`, `escrow-recipients.txt`, `README.md` and `history/<env>/<YYYYMMDDTHHMMSSZ>.sops.yaml`, where `<env>` is `[a-z][a-z0-9_-]*`.
  - A `*.sops.yaml` that does not parse as a single YAML mapping, including a `ValueError` or `RecursionError` from construction, is reported as `sops-metadata-missing`.
  - The metadata check needs a top-level `sops` dict with a non-empty `age` list and a non-empty string `mac`.
- CLI `secret_scan.py [--root DIR]`:
  - prints one finding per line on stdout, plus a one-line count summary on stderr;
  - exits 1 on any finding, 0 when clean, and 2 when the scan cannot run (git failure or an unreadable file).
- SOPS conventions (R-01.18) are written in the module docstring for WS-03.8:
  - only the planned file set lives under `deploy/secrets/`;
  - every file is fully encrypted: no `unencrypted_suffix`, `unencrypted_regex` or `encrypted_regex`, and no key ending in SOPS's default `_unencrypted` suffix;
  - no `*.agekey` or `keys.txt` file exists anywhere in the tree;
  - keys arrive through `SOPS_AGE_KEY_FILE` at deploy time, and plaintext exists only on tmpfs.

## Choices beyond the brief's minimum (all stricter, none changes a tested behaviour)
1. **The plaintext check walks the composed YAML node graph**, not the constructed dict, through one `SafeLoader` pass: `get_single_node` followed by `construct_document`. The reason is that PyYAML's last-key-wins rule would otherwise let a duplicate key (`A: plaintext` then `A: ENC[...]`) hide a plaintext value. A visited-node set means an alias is walked once. That bounds "billion laughs" files (7 ms) and stops recursive anchors from looping.
2. **Name matching is case-insensitive for detection.** `KEYS.TXT`, `x.AGEKEY`, the `deploy/secrets/` prefix and the `.sops.yaml` suffix all trigger checks. Two things stay case-sensitive: the exemption for the creation-rules file `.sops.yaml` and the planned-file names (so `readme.md` is stray). Git on Windows uses `core.ignorecase`, so case variants behave differently across hosts. Matching them anyway makes the scan the stricter, host-independent guard.
3. **Defence in depth on `history/`.** `.gitignore` allows `history/**/*.sops.yaml` at any depth, as the brief specifies. The scan accepts only `history/<env>/<UTC timestamp>.sops.yaml` and flags anything deeper or misnamed as stray.
