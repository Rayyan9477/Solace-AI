## Design notes and deviations

1. **LIF-1 conformance is strict.** Form (a) must be the lifespan's only statement, with exactly one context manager and the target `runtime`, and a `yield` inside. Form (b) is exactly two statements: the start, then a `try` whose `finalbody` is exactly the stop and whose body contains the `yield`. Anything after the bracket is rejected. `service_runtime` looks up `start_service_runtime` through bootstrap's globals, so `_conformance_probe.py`'s patch still stops right after start. The probe test passes on reference_app in form (a).
2. **The IF-01 logging chain names are unchanged.**
   - PHI-1 is a subclass of structlog's `ExceptionRenderer` that fills the `format_exc_info` slot in both chains. `logging_chain_names()` still reports `format_exc_info`, so `RUNTIME_CHAIN` and the test_mvp_180 chain test hold.
   - PHI-3 lives inside `redact_credentials` and adds no new processor.
   - Reason: the brief says other IF-01 names stay unchanged, and the conformance suite asserts that exact chain.
3. **PHI-1 covers every path, plus a backstop.**
   - Every path is covered: structlog `.exception`, stdlib `.exception`, `background_task_exited`, the 500 line, and asyncio's handler.
   - `_log_server_fault` also walks the chain itself, so the HTTP path stays safe even when the runtime chain is not configured.
   - Backstop: rendered traceback text that still contains `input_value=` (a ValidationError's text copied into another message) is dropped, with `validation_errors: []`.
   - Trade-off: when a ValidationError is in the chain, the whole traceback is dropped. Only `error_type`, the masked fields and the top-level `origin` remain.
4. **PHI-2 warnings capture.**
   - `py.warnings` is added to `ROUTED_STDLIB_LOGGERS` (new constant `WARNINGS_LOGGER`).
   - Each configure resets capture with `captureWarnings(False)` then `captureWarnings(True)`, because `captureWarnings(True)` does nothing after a `catch_warnings()` block has put `showwarning` back.
   - `_WarningFilter` rewrites `input_value=` records. ExtraAdder now also allows `warning_category`.
5. **PHI-3 normalisation.**
   - Non-JSON values become exactly what JSONRenderer would have printed (`__structlog__()` or `repr`), now scrubbed. Bytes go through `repr` and are then scrubbed, not replaced with a placeholder.
   - Dict keys become strings. Keys matching the sanitizer's `DEFAULT_PATTERNS` become `[key]`, with `#2` and so on for collisions. Key masking is on only when the sanitizer is loaded.
   - Side effect: dicts keyed by IP addresses or dates get `[key]` keys. That matches the sanitizer's policy for values.
6. **PHI-4 shared masking.** The masking now lives in one place: `logging._masked_field_path` (with `_field_path`, `_raise_site` and `_validation_error_fields`).
   - The 422 body (`_validation_detail`), the 500 line, the renderer and the lifespan filter all use it.
   - `http._validation_error_summary` is replaced by `_validation_error_fields`.
   - The lifespan summary is now masked and capped at 50 too.
7. **LIF-2.** `register_background_task` registers a cancel-and-await step named after the task. `_start_readiness_refresher` no longer registers its own `_stop_refresher`; it gets the same step, name and order from `register_background_task`. Guidance (also in the shape note): register a task's graceful stop after the task, so the graceful stop runs first.
8. **LIF-3.** New public constant `SHUTDOWN_CANCEL_GRACE_SECONDS = 1.0`.
9. **LIF-4.** `_close_postgres_pools` clears the registry in a `finally` (`_forget_postgres_pools`): it terminates any pool still registered, then clears `_pools`, `_pool_configs` and `_locks`.
10. **LIF-5.**
    - `stop_service_runtime` first marks the runtime stopping: a private flag, cache invalidated, `solace_service_ready` set to 0.
    - While stopping, `evaluate_readiness` runs no checks and returns not-ready with empty checks.
    - Once all closers have run, the runtime is detached from `app.state`. A cancelled stop stays attached but stopping, so `/ready` is still 503.
    - `/live` is unchanged.
    - No new public name was added: the flag and the attach/detach methods are private.
11. **HTT-2.**
    - `RequestBodyLimitMiddleware` is innermost, inside `RequestContextMiddleware`. The comment now places WS-04.6's rate limiter between the two.
    - The 413 adds `Connection: close`. The message text, "Request body too large", is my choice; the brief gives none.
    - After a cut-off, any exception the app raises is swallowed and answered with the 413, without a log line.
    - New public names: `RequestBodyLimitMiddleware` and `REQUEST_TOO_LARGE_CODE`.

## Concerns

- **The error code `request_too_large` is lower case,** as the brief says verbatim. The other envelope codes are upper case (`INTERNAL_ERROR`, `BAD_REQUEST`, `VALIDATION_ERROR`). The owner may want `REQUEST_TOO_LARGE`; changing it is a one-line constant change plus tests.
- **LIF-4 couples the runtime to WS-02 internals.** It reaches into `ConnectionPoolManager`'s private registries. If WS-02.6 later makes `close_pool` / `close_all_pools` clear in a `finally`, the runtime step becomes redundant but stays harmless.
- **One startup line is not JSON (pre-existing, not in scope).** `ProductionGuards` logs `production_security_validation_passed` before `configure_service_logging` runs, so that line prints as console text on stdout (seen in the uvicorn probe). uvicorn's two pre-lifespan stderr lines are expected under the ordering contract.
- **No lifespan shape covers SIGTERM during startup.** uvicorn skips the lifespan shutdown in that case; the audit records the same caveat.
- **Phase B is running concurrently.** The bootstrap per-service counts will keep moving as lanes land, and the head tree includes their in-progress files.

### Notes

- **Key name in reduced dicts.** I named the reduced dict's location key `field` (a masked dotted path), not `loc`. That matches every other validation summary (`validation_errors` entries from the renderer, the 500 line and the lifespan filter), so a reader sees one shape everywhere. If the controller wants the key to stay `loc`, it is a one-key change in `_reduced_error_dict`.
- **`msg` also triggers the reduction.** A `value_error`'s `msg` is the validator author's text and can quote the input. So a deliberately input-stripped `errors(include_input=False)` list also loses its `msg` in logs.
- **The pattern still matches on the key name.** A logged string that merely mentions a quoted `input` key followed by a colon, such as a JSON payload with an `input` field, is cut. This is the same fail-closed trade-off the reviewer accepted in fix round 1.
