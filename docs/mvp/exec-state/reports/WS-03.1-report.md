## Concerns

1. **The test harness did not run exactly as the brief wrote it.** The changes are in my own files only.
   - (a) portkey-ai 1.9.10 (runtime lock) installs a top-level `tests` package into site-packages (`portkey_ai-1.9.10.dist-info/RECORD`). It shadows the repo's `tests` namespace, so `from tests.deploy.conftest import REPO` failed. `tests/deploy/conftest.py` now registers itself as `sys.modules["tests.deploy.conftest"]`. Every later WS-03 test uses that import, so this must stay. **The packaging defect affects any `tests.*` import anywhere in the repo**, for example a clean CI venv. Suggest a ruling, such as `tests/__init__.py` or a lock note.
   - (b) The `pytest_collection_modifyitems` hook is global. It is now limited to items under `tests/deploy`. Unscoped, it would skip the realinfra/e2e tests in `tests/build` and `tests/migrations` whenever suites share one pytest process.
   - (c) `Rendered.__repr__` lists only service names, so generated values stay out of assertion output.
2. **`compose_render` departs from the brief in three places.** Each was needed for correctness:
   - (a) `ProgramFiles` is added to the scrubbed environment. Docker Desktop's compose plugin is in `%ProgramFiles%\Docker\cli-plugins`; without it `docker compose` is not found.
   - (b) The `.env.prod` placeholder holds a probe variable, and services that receive it are reported as `env_file: [".env.prod"]`. Compose v5's `config` inlines env_file and drops the key, which made `test_no_service_reads_an_env_file` vacuous: it passed on the old files before this change.
   - (c) `$$` is unescaped to `$` in `environment` values, because compose's output escapes `$`. Without this, WS-03.5's `test_single_quoted_hash_reaches_caddy_intact` could never pass.
3. **Scope additions beyond the Files line.**
   - Bare `POSTGRES_PASSWORD` now reaches all nine app services (dev default unchanged, `:?` in strict). `ProductionGuards.DEFAULT_REQUIRED_IN_STRICT` requires it on every service, and until now it came only from `env_file: .env.prod`, which is removed. This overlaps WS-03.2, which owns the IF-02 Postgres block and the dev-default change.
   - The legacy DB password aliases and `SAFETY_REPO_POSTGRES_DSN` are now `:?` in strict. Before, they silently used the base dev default.
   - In strict, `WEAVIATE_API_KEY` moved from the weaviate container, which never reads it, to memory-service, which does. Weaviate keeps `AUTHENTICATION_APIKEY_ALLOWED_KEYS :?`. In dev, memory-service now also gets the dev key; before, it had none.
4. **The registry does not cover every service yet.** Grafana, redis, kafka, zookeeper, jaeger and prometheus are not registered. As a result, `test_no_dev_default_survives_in_strict` does not see Grafana's admin/admin reaching strict (MVP-040, WS-03.3). Registering it now would turn this task red on a WS-03.3 defect.
5. **Synthetic-values semantics.**
   - strict = ENVIRONMENT + every required source + each non-secret source that has an `example`. Optional secrets stay unset.
   - dev = ENVIRONMENT only, so committed defaults apply. This keeps WS-03.2's MVP-116 test red as planned.
   - Consequence: the leak test assumes the operator supplies every example. SMTP_HOST=mailhog and SMTP_PORT=1025 still survive a strict deploy that omits them (MVP-042, WS-03.6, W1).
6. **Effects on downstream lanes.**

The current `EncryptionSettings` accepts only exactly 32 bytes until WS-09.1 lands, so a strict boot with a hex64 key before then fails PHI-encryption startup. ### Changes

1. **(important) Docker gate.** `tests/deploy/conftest.py` no longer uses `xfail(run=False, strict=True)`. It follows the tests/bootstrap pattern:
   - a `_DOCKER_MISSING = pytest.StashKey[str]()`;
   - the collection hook stashes "SOLACE_RUN_DOCKER_TESTS/SOLACE_REQUIRE_REALINFRA set but docker CLI not on PATH";
   - a new `pytest_runtest_setup(item)` calls `pytest.fail(reason, pytrace=False)`.

   An opted-in realinfra tier with no docker CLI now fails instead of passing. A new test, `test_docker_gate_fails_when_the_cli_is_missing`, proves it: it sets SOLACE_REQUIRE_REALINFRA=1, monkeypatches `shutil.which` to return None, and runs both hooks on a fake realinfra item. It asserts the item gets no skip or xfail marker and that setup raises `pytest.fail.Exception` with the reason.
2. **Raw-YAML `env_file` check.** `test_no_service_reads_an_env_file` now also loads each file in `PROFILES["strict"]` and asserts that no service declares `env_file`, which catches optional entries the render probe cannot see. It does not use bare `yaml.safe_load`: it uses a SafeLoader subclass that reads compose tags (`!reset`, `!override`) as plain nodes, because WS-03.3 adds `ports: !reset []` to the prod file in W0 and `safe_load` would raise on that tag.
3. **Required-only leak check.** New `test_strict_with_only_required_sources_keeps_no_dev_default` renders strict with only the required sources plus ENVIRONMENT. Every non-required strict row whose source is not itself required must then equal its `strict_default` or "". The allow-list is exactly `{("notification-service","EMAIL_SMTP_HOST"), ("notification-service","EMAIL_SMTP_PORT")}  # MVP-042, removed by WS-03.6`.
4. **Prod header reworded** (`docker-compose.prod.yml` lines 3-5 and 11-15) to describe what compose actually does:
   - `--env-file` replaces a dev `.env`, but a variable already set in the shell that runs compose overrides that file, so compose must run from a clean environment;
   - `${VAR:?...}` only checks that a value is set and non-empty, and compose does not check that ENVIRONMENT is staging or production, so that must be enforced before compose runs.
5. `test_mvp_231_config_service_removed.py` now uses `names = set(r.services)` and asserts on `names`, so a failure prints only names.
6. `test_p2_15_env_debug_disabled` now checks `ok = "DEBUG=false" in env_text and "DEBUG=true" not in env_text`, then `assert ok, "DEBUG must be false in .env"`. A failure can no longer print the .env file.
