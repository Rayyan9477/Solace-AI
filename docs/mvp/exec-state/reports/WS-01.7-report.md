## Deviations from the brief's verbatim test code (both close false-result holes; neither changes any owner map or value)
1. **The lint gate passed falsely in the required venv.** The venv is `--system-site-packages`, so ruff 0.6.9 comes from anaconda's site-packages, but the venv's `Scripts\` has no `ruff.exe`. As a result `python -m ruff` raises `FileNotFoundError: D:\tmp\mvp-exec\venv\Scripts\ruff.exe` and exits 1 with empty stdout. The brief's code accepts exit code 1 (`returncode in (0, 1)`) and then reads empty stdout as `json.loads(r.stdout or "[]")`, so **all four lint cases PASSED with ruff never running**. The evidence is the first, verbatim RED run in `WS-01.7-red-verbatim.txt`. Fix:
   - A new `_ruff()` helper uses `python -m ruff` when `python -m ruff --version` succeeds. Otherwise it falls back to `shutil.which("ruff")`, which here is `anaconda3\Scripts\ruff.exe` 0.6.9, the version the lock pins. If neither works, it fails loudly.
   - The `or "[]"` fallback is gone, so `json.loads(r.stdout)` is strict. ruff 0.6.9 prints `[]` when there are no findings (verified), so empty stdout now means ruff never ran, and the test errors.
   - In CI, `python -m ruff` works (`pip install ruff` puts the binary in the runner's Scripts), so CI behaves exactly as the brief intends.
2. **A UTF-8 BOM in any scanned file crashed every import case.** `read_text(encoding="utf-8")` followed by `ast.parse(str)` raises `SyntaxError: invalid non-printable character U+FEFF`. Python itself accepts BOM-prefixed source files. During my first run, WS-09.2's in-progress files (`services/shared/infrastructure/__init__.py`, `llm_client.py`) and `tests/integration/phi-codec-audit-llm/test_mvp_199_llm_init.py` had BOMs. That made **all 12 owner cases fail with SyntaxError, and the WS-10 strict-xfail was "satisfied" by that error rather than by its real violation**. Fix: read with `encoding="utf-8-sig"`, which is identical to utf-8 when there is no BOM.
