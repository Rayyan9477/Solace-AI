1. **Migrations must run as `solace_migrator`.** The default privileges are `FOR ROLE solace_migrator`. If a later slot runs as another role (the old compose superuser `solace`, or `postgres`), its tables are owned by that role and `solace_app` gets no DML on them. The `test_mvp_041_app_role_has_dml_but_no_ddl` owner assertion (`{solace_migrator}`) would catch that in tests. WS-02.4 (the migrate entrypoint) and WS-03.2 (compose) must keep the migrator DSN.
2. **009 fails loudly on a database without the IF-03 roles** (`role "solace_app" does not exist`), for example an old dev volume from before WS-02.1. This is intended under D-02, but such volumes must be recreated before they can upgrade past 008.
3. **Default privileges give new tables full DML.** Append-only or read-only tables in later slots must revoke what they should not allow. 011's docstring says this for `audit_events`, and the real-PG audit test enforces it once the table exists (it is vacuous today).
