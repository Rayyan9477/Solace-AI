## Deviations (for rulings)

1. **Event bridge is not unguarded outside strict.**
   - What changed: the brief's unguarded `initialize_event_bridge` made every dev/test boot without Kafka crash. That broke `test_oauth_endpoints.py::TestProductionAppGate` (a real `create_app()` under TestClient), which is not one of my files, and it would break dev boots without a broker.
   - What I did: followed the safety-service pattern (WS-12.1). In strict the bridge is unguarded, so a start failure is fatal. Outside strict the failure is logged as `user_event_bridge_unavailable` (error type only), and a critical readiness check `event_bridge` keeps `/ready` at 503.
   - Tests: 2 tests cover this.
2. **CORS in the docs test.** `test_mvp_328_status_is_gone_and_docs_follow_the_runtime` sets `CORS_ALLOWED_ORIGINS` through monkeypatch. The runtime refuses a strict edge app that has no origin list, so the brief's verbatim test cannot build the strict app.
3. **`StartupDependencyError` takes two arguments.** The runtime signature is `(component, reason)`, so the call is `StartupDependencyError("redis", "user-service identity stores require REDIS_URL")`.
4. **Strictness is wider than the brief's literal.** The checks use `is_strict_environment(SPEC.environment) or is_strict_environment()`, the platform rule from CLAUDE.md. The brief's literal was `is_strict_environment(SPEC.environment)` alone. `_rate_limiting_disabled` also refuses to disable in strict. This closes `USER_SERVICE_ENV=test` + `ENVIRONMENT=production`, a hole that the new `"test"` literal would otherwise open.
5. **Shutdown closer.** The old post-yield cleanup (shutdown log, `initialized=False`, `_state=None`) is now a closer named `user_service_state`. It is registered first, so it runs last.
